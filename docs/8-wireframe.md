## 0. 문서 목적 및 범위

본 문서는 PRD §8에 나열된 5개 화면의 **레이아웃과 구성 요소**를 텍스트/ASCII 다이어그램으로 정의한다. PRD §4가 확정한 "웹 우선, 별도 모바일 앱 없이 반응형 웹 UI로 모바일 브라우저 대응" 방침에 따라, 화면마다 **데스크톱 레이아웃**과 **모바일 레이아웃**을 각각 그린다.

- 다루지 않는 것(범위 밖, 도메인 정의서 §7·PRD §10·프로젝트원칙 §0과 동일): DB 스키마, API 명세, 실제 컴포넌트 코드, 색상/타이포그래피 등 비주얼 디자인 시스템, 인터랙션 애니메이션 세부.
- PRD/도메인 문서에 없는 화면·기능은 추가하지 않는다(오버엔지니어링 금지).
- 아래 모든 문구·수치 예시는 3-user-scenario.md에 등장한 값을 그대로 인용한다(임의 창작 금지).

### 0.1 브레이크포인트 기준

| 구분 | 폭 기준 | 비고 |
|---|---|---|
| 데스크톱 레이아웃 | 768px 이상 | 좌우 분할, 다열(多列) 표 등 넓은 화면 활용 |
| 모바일 레이아웃 | 768px 미만 (기준 시안 폭 375px~430px) | 상하 배치, 탭 전환, 카드 스택 등으로 재배치 |

같은 화면이라도 폭이 768px를 오르내리면 아래 두 레이아웃 중 하나로 전환된다(별도의 태블릿 전용 레이아웃은 만들지 않는다 — 오버엔지니어링 금지, PRD·프로젝트원칙 어디에도 태블릿 전용 요구가 없음).

## 1. 매물 탐색 지도/목록 화면 (F1)

지도(네이버지도 UI/UX 기반)와 매물 카드 목록을 함께 보여주는 진입 화면이다. 매매가 필터(7~15억 기본)로 조건을 좁히고, 각 카드에는 매물 자체 속성(매매가·전용면적)과 소속 단지의 연식·최근접 셔틀 정류장·셔틀 통근시간이 함께 표시된다(도메인 §3.1, PRD F1). 조건에 맞는 매물이 0건이면 에러가 아닌 정상 상태 메시지를 표시한다.

하나의 매물 상세 화면 안에서 "규제/대출"(F4), "입지 정보"(F5), "대출 시뮬레이션"(F6), "매매가 변동 이력"(F7) 4개 탭을 전환한다(프로젝트원칙 §6 `listing-detail/` 셸 + 하위 4개 feature). 상단에는 매물 자체 속성(매매가·전용면적)과 소속 단지명을 공통 헤더로 표시한다.

각 화면에 대해 데스크톱/모바일 레이아웃이 명확히 구분되어(단순 텍스트 축소가 아니라 배치 구조 자체가 재구성되어) 설계되었는지 자체 점검한다.

- [x] 매물 탐색 지도/목록 화면(F1): 데스크톱은 지도+목록 좌우 분할, 모바일은 지도/목록 상단 탭 전환 + 목록은 세로 카드 스택으로 재배치됨
- [x] 매물 상세 화면(F4·F5·F6·F7 탭): 데스크톱은 탭 콘텐츠 좌우 2분할/그래프+테이블, 모바일은 가로 스크롤 탭 바 + 세로 스택(대출 시뮬레이션 시나리오 카드 세로 배치, 가격이력 테이블→카드형)으로 재배치됨
- [x] 즐겨찾기 화면(F2): 데스크톱은 상단 탭 전환 + 표 형태 리스트, 모바일은 세그먼트 탭 + 카드형 세로 스택 + 하단 고정 선택바로 재배치됨
- [x] 비교셋 화면(F3): 데스크톱은 축(행)×대상(열) 다열 표, 모바일은 대상 스와이프 전환 + 축 세로 아코디언(가로 스크롤 표 미사용)으로 재배치됨
- [x] 내 정보 화면(F6): 데스크톱은 라벨+입력 2열 병렬 배치, 모바일은 전체 필드 세로 1열 스택 + 저장 버튼 하단 고정으로 재배치됨
