## 1. 개요

**housing**은 수도권 8~12억원대 아파트 매수를 준비 중인 실사용자(부부)가, 삼성전자 화성/평택 캠퍼스 직주근접 조건을 기준으로 후보 아파트를 탐색·비교·의사결정하도록 돕는 개인용 반응형 웹 서비스다(별도 모바일 앱 없음, 모바일 브라우저에서 반응형 UI로 대응). 회원가입/로그인 없이 단일 사용자 프로필로 동작한다.

## 2. 목표

- 사용자가 원하는 지역·조건의 매물만 걸러서 비교할 수 있게 한다.
- 매물별 규제 현황과 대출 가능 금액을 즉시 계산해, "이 집을 실제로 살 수 있는가"에 바로 답한다.
- 삼성전자 셔틀 통근시간을 1급 비교 축으로 노출해 직주근접 의사결정을 지원한다.

## 3. 타겟 사용자

- 1인 사용자(또는 배우자와 함께 사용) — 수도권 8~12억 아파트 매수를 준비 중이며, 근무지는 삼성전자 화성 또는 평택 캠퍼스
- 별도의 회원 구분 없음(§4.2 참조) — 기기/앱 단위 단일 프로필

| 항목 | 결정 |

## 6. 기능 요구사항 및 인수 조건

### F1. 매물 탐색 및 셔틀 통근 분석
- 지도(네이버지도 UI/UX)에서 매매가 7~15억 구간 매물을 노출한다.
- 매물 카드/핀에는 매물 자체 속성(매매가, 전용면적)과 함께 소속 단지의 연식(준공년도 기반), 최근접 삼성전자 화성/평택 셔틀 정류장, 도보/차량 이동거리(500m 기준), 셔틀 통근시간을 함께 표시한다.
- **인수 조건**: 조건에 맞는 매물이 0건이면 "조건에 맞는 매물이 0건입니다"를 표시한다(에러 아님, 정상 상태).

### F2. 즐겨찾기
- 아파트 단지 카드/상세와 매물 카드/상세 각각에서 즐겨찾기 추가·해제 토글을 제공한다. 단지 즐겨찾기와 매물 즐겨찾기는 서로 독립된 목록으로 관리된다.
- **인수 조건**: 동일 단지/동일 매물 중복 즐겨찾기는 불가(대상별 토글 상태로만 존재). 단지 즐겨찾기에 추가한다고 해서 그 단지의 매물이 매물 즐겨찾기에 자동 추가되지는 않는다(두 목록은 독립).

### F3. 비교셋 생성 및 비교
- 비교셋 생성 시 비교 대상 유형(**단지 비교** 또는 **매물 비교**)을 먼저 선택한 뒤, 해당 유형의 즐겨찾기 목록에서 2~5개를 선택해 비교 화면을 구성한다. 하나의 비교셋 내 대상은 동일 유형이어야 한다(단지와 매물을 혼합 불가).
  - **단지 비교**: 서로 다른 단지를 대상으로, 그 단지의 기본정보(연식, 리모델링 이력, 재건축 추진현황, 주변 재개발 정보)와 "단지 시세"(그 단지에 속한 매물들의 매매가 MIN~MAX, 조회 시점 집계값, 비영속)로 비교한다.
  - **매물 비교**: 매물을 대상으로, 서로 다른 단지에 속한 매물 간 비교와 동일 단지에 속한 매물끼리의 비교를 모두 지원한다. 매물 자체 속성(매매가, 전용면적)과 소속 단지의 기본정보를 함께 비교한다.
- 비교 축: 연식, 리모델링 이력, 재건축 추진현황, 주변 재개발 정보, 교통(지하철/광역버스/시내버스), 상권, 학군(학교/학원가), 강남 접근성, 유흥시설·공원 유무, 셔틀 통근시간, 개발 호재, 주변 일자리(대기업 등), 그리고 (단지 비교 시) 단지 시세 또는 (매물 비교 시) 매매가·전용면적.
- **인수 조건**: 6개 이상 선택 시도 시 선택을 막고 안내 메시지를 표시. 1개만 선택된 상태에서는 비교 화면 진입 불가. 이미 포함된 대상(단지 또는 매물)을 동일 비교셋에 다시 추가하려는 시도는 "중복입니다" 팝업을 띄우고 추가하지 않는다(DB UNIQUE 제약으로 최종 방지, database/schema.sql 참조). 동일 단지 내 매물끼리 매물 비교를 하는 경우 단지 축(연식 등)이 모든 대상에서 동일하게 표시되는 것은 정상 동작이다.

### F4. 매물 상세 - 규제/대출 분석
- 매물이 속한 **단지**의 토지거래허가구역·투기과열지구/조정대상지역 여부와, 그 매물의 매매가를 기준으로 산출한 최대 대출가능금액, 갭투자 가능 여부, 실거주 필수 기간을 표시한다(도메인 §5.1~§5.2 로직 적용).
- **인수 조건**: 소속 단지의 규제지역 여부가 미확정인 매물(예: 평택 등)은 "확인필요" 배지를 표시하고, 비규제지역 LTV를 하한값으로 임시 적용한 금액임을 명시한다.

### F5. 매물 상세 - 입지 정보
- F3과 동일한 입지 축(교통/상권/학군/강남 접근성/유흥·공원)과 단지 기본정보(연식/리모델링/재건축/주변 재개발 정보)를, 매물이 속한 **단지** 기준으로 조회하여 단독 매물 상세에서 표시한다.

### F6. 매물 상세 - 대출 시뮬레이션
- 앱 최초 진입 시 명의 구성, 소득, 성과금, 자본금, 세대 주택 보유 구분(무주택/1주택[오피스텔 포함]/다주택)을 입력받아 프로필에 저장한다.
- "내 정보" 화면에서 위 값을 언제든 수정할 수 있으며, 수정 즉시 전체 매물 상세의 대출 시뮬레이션이 재계산된다.
- 매물의 매매가와 소속 단지의 규제 정보를 기준으로 부부합산 명의 vs 단독 명의 두 시나리오의 최대 대출가능금액과 10/20/30년 원리금균등상환액을 계산·비교하고 유리한 쪽을 안내한다(도메인 §5.3~§5.4 로직).
- 디딤돌대출·보금자리론 등 정책모기지는 계산 범위에서 제외하고, 필요 시 사용자가 직접 확인하라는 안내 문구만 노출한다.
- **인수 조건**: "내 정보" 미입력 상태에서는 대출 시뮬레이션 영역에 입력 유도 화면을 표시하고, 다른 기능(F1~F5, F7)은 정상 이용 가능해야 한다.

### F7. 매물 상세 - 20년 매매가 변동 이력
- 매물이 속한 **단지** 단위로, 국토교통부 아파트 실거래가 공개시스템(오픈API)를 출처로 최근 20년 매매가 변동 그래프를 표시한다(실거래가 데이터 자체가 단지 단위 이력이므로 개별 매물이 아닌 소속 단지 기준으로 관리·표시).
- 실거래 데이터가 20년 미만이면 최초 거래 시점 이후 데이터만으로 그래프 + 거래일자/거래금액 테이블을 표시하고, "최초거래(YYYY-MM) 이후 데이터" 안내를 함께 노출한다.
- 실거래 데이터가 0건이면 "실거래 이력 없음"을 표시한다.

## 9. 리스크 및 가정

- **단지 기본정보(연식/리모델링/재건축/주변 재개발 정보) 데이터 출처**: 이 정보들을 한 번에 제공하는 공식 API가 없어, 공공데이터(정비사업 정보몽땅, 국토교통부 등) 조합 또는 수동 리서치로 확보해야 한다. 어떤 출처를 단지별 기본값으로 채택할지, 갱신 주기는 어떻게 할지 개발 착수 전 후속 선정이 필요하다.
- **상권/학군/개발호재 데이터**: 호갱노노·네이버부동산은 크롤링 대상이 아니라 기능/UX 참고 사례일 뿐이며, 실제 데이터는 소상공인시장진흥공단 상권정보·학교알리미 등 공공데이터로 채운다. 어떤 공공데이터로 각 지표를 산출할지는 개발 착수 전 구체적으로 선정해야 한다.
- **셔틀 배차 데이터**: sbus.u-vis.com 포털이 구조화된 공개 API를 제공하지 않을 가능성이 있어, 데이터 확보 방식(수동 조사/정기 갱신)을 개발 착수 전 확정해야 한다. 임직원 전용 페이지일 경우 접근 권한(로그인) 필요 여부도 확인이 필요하다.
- **지도 UI**: 네이버지도 API 이용약관상 본 서비스 목적(부동산 정보 서비스)으로 사용 가능한지 확인이 필요하며, 제약이 있을 경우 구글맵으로 대체한다.
- **정책 데이터 최신성**: 규제지역·LTV 등 정책 수치는 자동 갱신되지 않으므로, 실제 서비스 운영 시 주기적 수동 갱신 담당(본인)이 필요하다.
- **단일 사용자 전제**: 사용자 프로필은 서버 DB(PostgreSQL)에 고정 ID의 단일 레코드로 저장된다. 인증이 없어도 어느 기기/브라우저에서 접속하든 동일한 프로필 값을 보게 되며, 다중 기기 동기화를 별도로 구현할 필요 없이 자연스럽게 달성된다.

## 10. 범위 밖 (Out of Scope)

DB 스키마, API 상세 명세, UI 와이어프레임, 코드 구현, 회원 인증 체계, 디딤돌대출·보금자리론 등 정책모기지 계산, 다중 기기 동기화 — 도메인 정의서 §7과 동일하게 본 PRD도 이번 버전에서는 제외한다.
